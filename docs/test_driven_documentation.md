# Test-Driven Documentation ("Жива" документація)

Цей розділ описує підхід, де тести є одночасно:
- перевіркою коректності;
- виконуваними прикладами використання інструментів;
- коротким operational runbook для розробника.

Основний файл: `tests/test_living_documentation.py`.

## Які сценарії покрито

1. **`test_filesystem_tools_end_to_end_workflow`**  
   Демонструє повний сценарій роботи з файловими tool-ами:
   - створення директорії;
   - запис файлів;
   - листинг;
   - пошук за glob;
   - читання кількох файлів;
   - підсумкова статистика файлової структури.

2. **`test_server_roots_management_workflow`**  
   Показує runtime-керування дозволеними root-директоріями:
   - додавання root;
   - перевірка ефективного списку;
   - видалення root.

3. **`test_monitoring_tools_snapshot_workflow`**  
   Показує health-check сценарій для monitoring tool-ів:
   - знімок CPU/RAM;
   - статус дисків;
   - системна інформація хоста.

## Як запускати

Запуск тільки "живої" документації:

```powershell
pytest -q tests/test_living_documentation.py
```

Запуск одного сценарію:

```powershell
pytest -q tests/test_living_documentation.py -k filesystem_tools_end_to_end_workflow
```

## Принципи підтримки

- Якщо змінюється контракт tool-а, оновлюється відповідний сценарій у тесті.
- Якщо додається новий важливий інструмент, додається новий сценарний тест як приклад використання.
- Імена тестів мають бути «бізнес-читабельними» (workflow-oriented), щоб їх можна було читати як документацію.
